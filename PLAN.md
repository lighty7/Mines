# Mines Game — Android (Kotlin + Jetpack Compose)

A Stake-style Mines game rebuilt as a native Android app with its own dark casino
aesthetic. v1 is a **demo** (fake balance, local board generation) architected so a
real-money backend + provably-fair layer can be swapped in later without rewriting UI.

---

## 1. Decisions

| Area         | Decision                                                        |
|--------------|-----------------------------------------------------------------|
| Platform     | Android, Kotlin, **Jetpack Compose** (Material 3)               |
| UI style     | Dark casino theme, custom SVG gem/mine (no emoji), green accent |
| Money model  | Fake balance (demo). Repository interface is the backend seam.  |
| v1 scope     | Core manual game only. History/autoplay/sound/faireness = later.|

## 2. Architecture (MVVM + clean layers)

```
app/src/main/java/com/minesgame/
├── data/
│   ├── model/        GameState, TileState, Tile, GameResult
│   ├── engine/       MinesEngine        (pure math + board gen, no Android deps)
│   └── repository/
│       ├── GameRepository        (interface)
│       └── LocalGameRepository   (fake: local board, fake balance)
├── ui/
│   ├── theme/        Color.kt, Theme.kt, Type.kt
│   ├── components/   GridTile.kt (TileView + MinesGrid), Controls.kt
│   ├── screen/       GameScreen.kt
│   └── viewmodel/    GameViewModel   (explicit state machine)
└── MainActivity.kt
```

- `MinesEngine` = pure Kotlin, unit-testable.
- `GameViewModel` = single source of truth; enforces the state machine.
- `GameRepository` = seam where a remote API plugs in later
  (`createBoard(mines)` becomes `suspend`, board comes from server).

## 3. Game engine (math)

- Board: 25 tiles, `M` mines (1–24), placed via `SecureRandom` Fisher–Yates shuffle.
- Multiplier progression (1% house edge / 99% RTP):

```
P(safe at step i) = (25 − M − i) / (25 − i)

multiplier(K) = 0.99 / ∏_{i=0..K−1} P(safe_i)

potentialWin = bet × multiplier(K)
```

- Pure functions: `generateBoard(mines)`, `isMine(board, index)`,
  `multiplierAt(mines, revealed)`, `potentialWin(bet, mines, revealed)`.

## 4. State machine

```
GameState: IDLE → ACTIVE ─┬─(hit mine)→ LOST
                          └─(cash out) → WON

TileState: HIDDEN → REVEALING → SAFE | MINE
```

Forbidden (enforced in ViewModel):
- `WON` → reveal, `LOST` → cash out, `ACTIVE` → change bet/mines.

## 6. Data model

```kotlin
data class Tile(index: Int, isMine: Boolean, state: TileState = HIDDEN)
enum class TileState { HIDDEN, REVEALING, SAFE, MINE }
enum class GameState { IDLE, ACTIVE, WON, LOST }
data class GameResult(won: Boolean, multiplier: Double, payout: Double)
```

## 7. Dependencies

- Compose BOM `2024.12.01`, Material3, `activity-compose`, `lifecycle-viewmodel-compose`
- `kotlinx-coroutines` (flows), `JUnit4` (engine tests)
- AGP `8.7.3`, Kotlin `2.0.21`, Gradle `8.9`, compileSdk 35, minSdk 24, targetSdk 35

## 8. Build order

1. Theme (colors/typography)
2. `MinesEngine` + unit tests
3. `GameViewModel` state machine
4. UI: grid, tiles, bet/mine controls, cashout
5. Balance + win/lose flow
6. Reveal/mine animations (light polish)

## 9. Build / run

- Open the project root in Android Studio, let Gradle sync, then run on an emulator/device.
- (The `gradle-wrapper.jar` binary is regenerated by Android Studio on first sync.)
